# Windows installer and portable builds

The desktop builder uses the pinned `oonalang/phoenix` revision in `package.json`. The Windows shell uses Tauri 1.x.

## Run with GitHub Actions

1. Open the **Actions** tab of `oonalang/phoenix-desktop`.
2. Open **Build Phoenix Windows installers and portable ZIPs**.
3. Select **Run workflow**, then choose **both**, **modern**, or **legacy**.
4. Once the workflow completes, open the run and download the Artifacts.

Artifacts:

| Artifact | Files | Intended OS |
| --- | --- | --- |
| `phoenix-windows-modern-portable` | Portable application ZIP | Windows 10 / 11 |
| `phoenix-windows-legacy-portable` | Experimental portable application ZIP | Windows 8 / 8.1 |
| `phoenix-windows-modern-installer` | NSIS setup executable | Windows 10 / 11 |
| `phoenix-windows-legacy-installer` | Experimental NSIS setup executable | Windows 8 / 8.1 |

Both variants are unsigned. A portable artifact is a ZIP generated by GitHub Actions.
Extract all files and launch `Run Phoenix Portable.cmd`. You do not need to run the setup executable.
The ZIP includes the app executable, `phnode.exe`, the installed `src-node` backend, supporting DLLs,
and a launcher. The launcher creates a local WebView2 user-data directory. Editor settings and other
application data still use the Windows user profile. This is portable application distribution, not
complete profile roaming.

## Windows 8 and 8.1

Legacy builds are **experimental**. Building a ZIP does not prove the app runs on Windows 8 or 8.1.
WebView2 Runtime 109 was the last supported release on Windows 8 / 8.1. The `legacy` portable artifact
does not automatically include that runtime. A compatible runtime must already be installed, or an official
extracted x64 fixed runtime placed in the `WebView2Runtime109` folder beside the app executable.
The launcher selects that folder when present.

If the build runner already has `src-tauri/WebView2Runtime109/msedgewebview2.exe`, packaging will copy
the complete folder. No unsupported runtime is silently downloaded. The existing legacy NSIS mode
uses an embedded WebView2 bootstrapper, which still requires Internet access when installation is necessary.

The Tauri native executable, bundled `phnode` binary (currently downloaded from the latest release),
Node native modules, terminal, and editor web APIs still need testing on actual Windows 8 and 8.1 systems.
WebView2 109 and these Windows versions no longer receive security updates.

## Local build

Run on a Windows machine with Rust and the repository's build prerequisites installed:

```powershell
npm ci
npm run _ci-release:dev
node src-build/prepareWindowsBuild.js modern
npx tauri build --config src-tauri/tauri-custom.conf.json
node src-build/packagePortableWindows.js modern
```

For an experimental Windows 8/8.1 package, replace `modern` with `legacy`.
The staged portable folder appears under `dist/portable/`.

## Troubleshooting

If the editor does not open, check the Windows runtime prerequisites, included sidecar,
and GitHub Actions build logs. Run a full smoke test for startup, file operations, AI
completions, extensions, terminal, and live preview before publishing a stable release.
